What this section will cover when taught
• Two retries in the same call path: Instructor's own retry (fixes bad shape) vs tenacity's outer retry (fixes bad call). Deliberately separate, not stacked without thought.

Section 4

Rate limiter — reject locally, don't retry into a wall

A sliding-window limiter over the two live-measured caps (5/min, 20/day), checked before the network call. And why the tests use an injectable clock, not real sleeps.

queued · not yet taught
Anchor file
src/narration_enrichment/rate_limiter.py
Commit
4899753
What this section will cover when taught
• Why reject-locally beats waiting for the provider's own 429: the daily cap doesn't recover inside any retry window, so retrying is guaranteed-fail plus quota burn.
• Sliding window as arithmetic on a deque of timestamps — pure Python, no Redis. Same "smallest infra" rule as SQLite-for-RAG.
• Injectable time_fn: tests prove a 60-second window reset without a real 60-second sleep. The mechanism under test is arithmetic, not LLM behavior — mocking the clock is the right tool.

Section 5 · has a bug story worth studying

Correlation IDs + the logging-filter bug caught live

Python's contextvars.ContextVar as the async-safe MDC, and a subtle Logger.addFilter() vs Handler.addFilter() difference that silently makes the filter never run.

queued · not yet taught
Anchor file
src/narration_enrichment/correlation.py
Commit
3f8985d
Cross-track parallel
ticketing's CorrelationIdFilter (same shape, Java thread-local MDC)
What this section will cover when taught
• Why ContextVar works cleanly in async Python without the finally { MDC.remove() } Java's thread-local needs — Starlette runs each request in its own Task, and a ContextVar set inside a Task is invisible to every concurrently running Task.
• The bug: attaching the filter via logging.getLogger().addFilter(...) looked right, but Logger.filter() is only invoked by the logger that originates a record — propagation to ancestors calls the ancestor's handlers, bypassing its own filter. Fix: handler.addFilter(...).
• The test lesson: pin the bug in an isolated logger tree, not the real root. The real root already carries the fix by the time main.py imports, which would silently mask the very bug being tested for.

Section 6

Degrade-not-fail — the pattern that runs through everything

RAG, embeddings, `/stats` on an empty table — all designed so a failure in a support path never turns the request path into an outage.

queued · not yet taught
Anchor files
rag.py (both embed calls in try/except), db.py (aggregation returns null not fake-0.0), main.py (exception mapping)
Commits
8fea40d (RAG degrade), 20cb3c6 (/stats null-not-zero)
What this section will cover when taught
• The rule stated concretely: a broken embedding call should cost that one row's future retrievability, not turn /enrich into a 500.
• /stats returns average_confidence: null (not 0.0) on an empty table — SQL's AVG() over zero rows is NULL, and reporting a fake 0.0 average would misleadingly imply there's data behind it.
• Exception mapping by type, not by string-matching messages — InstructorRetryException → 422, httpx.TimeoutException → 504, anything else → generic 500 that never echoes the exception message to the caller.
• Same pattern lives on the ticketing track — same principle, different language. This section is the place to make that parallel explicit.
