DAY 1 What actually crosses the wire
day1_raw_call.py
Goal

No framework, no schema — wire the raw google-genai SDK, send one narration, and look at exactly what gets sent and what comes back.

Code
request_payload = {
    "contents": [{"role": "user", "parts": [{"text": prompt}]}],
    "generationConfig": {"maxOutputTokens": 300},
}
response = client.models.generate_content(model=MODEL, contents=prompt, config={"max_output_tokens": 300})
Real output — first run
Response text: In plain English, this is a **payment made to Swiggy... (cuts off mid-sentence) input_tokens: 50 output_tokens: 12 total_tokens: 346 finish_reason: MAX_TOKENS
Bug found

total_tokens (346) didn't equal input (50) + output (12) = 62. The missing 284 tokens were spent on invisible "thinking" — gemini-3.6-flash reasons before answering, and that reasoning shares the same max_output_tokens budget as the visible reply. A 300-token budget left almost nothing for the actual answer.

Fixed
finish_reason: STOP thinking_tokens: 489 output_tokens: 132 ← the visible answer above
DAY 2 Breaking the naive approach on purpose
day2_naive_json.py
Goal

Ask for JSON with a deliberately casual prompt — no "ONLY JSON", no field types spelled out — and parse the raw text with plain json.loads(). No safety net.

Prompt used (word for word)
Look at this bank transaction narration and tell me the
merchant, the category, the transaction type, and how confident you are.

Narration: {narration}

Give me this as JSON.
Real output — three narrations, three different failures
NarrationWhat came backFailure
...SWIGGY...```json {...} ```fence
...SALARY..."confidence": "High"wrong type
...AMAZON..."confidence": {"score":.98,"level":"Very High"}wrong shape
What actually crashed

json.loads() failed on all three — every response was wrapped in a markdown fence, so parsing died on the backtick before it ever reached the "High" string or the nested object. Data that was arguably still usable never even got read.

The twist

A more careful prompt (Day 1's — "Return ONLY a JSON object with exactly these fields...") had produced clean output on these same narrations. Better wording helped — but it's not a guarantee, and this project needed one.

DAY 3 Forcing the shape instead of hoping for it
models.py · day3_structured_output.py
The schema (models.py)
class TransactionEnrichment(BaseModel):
    merchant: str
    category: Literal["food_delivery","shopping","salary","transfer","other"]
    transaction_type: str
    confidence: float = Field(..., ge=0.0, le=1.0)
Same prompt, same narrations as Day 2 — new call site
client = instructor.from_genai(raw_client, model=MODEL)
result = client.create(
    response_model=TransactionEnrichment,
    messages=[{"role": "user", "content": prompt}],
    max_retries=3,
)
Real output — all three, this time
type: TransactionEnrichment ← a real object, not a dict confidence: 0.95 (float)

Not luck, and not a smarter prompt — Gemini's native function-calling (Instructor's default Mode.TOOLS) makes the model call a function shaped exactly like the schema. A string can't land in a float-typed argument slot; the fence and the nested object aren't things a function call can even produce.

Go deeper — the reask mechanism, from Instructor's own source

Verified in instructor/v2/providers/genai/handlers.py. On a validation failure, reask_genai_tools() builds the next attempt's conversation:

error_msg = f"Validation Error found:\n{exception}\nRecall the function correctly, fix the errors"
function_response_part = types.Part.from_function_response(
    name=function_call.name,
    response={"error": error_msg},
)

from_function_response(...) is normally how a real tool's real result gets reported back to Gemini after it calls one. Instructor reuses that exact channel to report a validation failure instead — Gemini has seen this shape of turn thousands of times in training as "a tool call didn't work, try again," and reacts to it far more reliably than a bolted-on text message would get.

In retry.py, only four exception types are treated as retryable at all: ValidationError, json.JSONDecodeError, AsyncValidationError, ResponseParsingError. Anything else — a network timeout, an auth failure — is not retried; it propagates immediately. That's a deliberate split: a shape problem is worth asking the model to fix, an infrastructure problem is not something asking the model again will ever solve.

max_retries=3 becomes stop_after_attempt(4) — one original attempt plus three reasks, maximum. Every attempt is a full, billed API call.

Go deeper — why patch("...main.enrich_narration"), not "...service.enrich_narration"

main.py runs from narration_enrichment.service import enrich_narration. That import binds a second name to the same function object — inside main's own namespace. When the route handler runs, it looks up enrich_narration in its own module's namespace, not back in service.

Patch service.enrich_narration and main's copy of the name is untouched — the real function still runs. The patch has to target the name where it's looked up at call time, which is wherever it was imported to, not wherever it was originally defined.
